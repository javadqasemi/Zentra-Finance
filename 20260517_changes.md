  ---
  Changed files

  1. package.json (rewritten)

  Why: The whole build/publish/auto-update pipeline lives here. Old config produced only a portable .exe via electron-packager — no installer, no
  latest.yml, no way for electron-updater to find updates.

  Key changes:
  - version: 0.1.0 → 1.0.0 (your choice)
  - Added repository, homepage, author — required so electron-updater can resolve the GitHub release feed
  - New scripts: release, release:draft, pack; removed build:legacy
  - postinstall now runs electron-builder install-app-deps (replaces manual electron-rebuild) — rebuilds better-sqlite3 for Electron's ABI on every
  install
  - Full build.win config with NSIS installer and portable target — NSIS is required for auto-update support
  - build.nsis: oneClick: false, perMachine: false (per-user install — no UAC), allowToChangeInstallationDirectory: true, desktop + start menu
  shortcuts, differentialPackage: true (downloads only diffs, not the full installer, on subsequent updates)
  - build.publish: GitHub provider, owner javadqasemi, repo Zentra-Finance, vPrefixedTagName: true — pairs with v1.0.0-style tags
  - rfc3161TimeStampServer configured (used once signing certs are added)
  - Moved electron from dependencies → devDependencies (electron-builder convention; otherwise it gets packed into the asar)
  - Added electron-updater + electron-log to dependencies (must ship inside the app)
  - Removed electron-packager (now redundant)

  2. main.js (edited)

  Why: No autoUpdater wiring, no window security hardening, no crash handler.

  Added:
  - electron-log import + log.catchErrors() — uncaught exceptions go to %APPDATA%\ZentraFinance\logs\main.log and pop a user-visible error dialog
  instead of silently crashing
  - shell import + setWindowOpenHandler — target="_blank" links / window.open() open in the user's default browser; the Electron window itself can't
   be hijacked
  - will-navigate handler — blocks in-app navigation away from file:// (allowing only localhost:5173 in dev)
  - will-attach-webview → preventDefault — defence in depth
  - webPreferences hardened: explicit sandbox: false (preload uses CommonJS), webSecurity: true, allowRunningInsecureContent: false
  - updater.init(mainWindow) called from did-finish-load

  3. src/updater.js (new file)

  Why: Keeps the ~150 lines of updater logic out of main.js.

  Features:
  - All 7 lifecycle events wired: checking-for-update, update-available, update-not-available, download-progress, update-downloaded, error, and a
  synthetic disabled event in dev
  - Forwarded to renderer over updater:event IPC channel as a typed payload
  - IPC handlers: updater:check, updater:download, updater:install, updater:status, updater:getVersion
  - autoDownload: false — user must opt in (avoids surprise bandwidth use)
  - Retry on transient errors (ENOTFOUND, ETIMEDOUT, ECONNRESET, net::*) up to 3× with 60 s backoff
  - Initial check 5 s after launch; periodic re-check every 4 hours
  - isDev() short-circuits everything when running npm start from source — no crashes from missing app-update.yml
  - Logs everything through electron-log

  4. src/preload.js (edited)

  Why: Renderer can't talk to autoUpdater directly with contextIsolation: true.

  Added: window.api.updater namespace — check(), download(), install(), status(), getVersion(), and an onEvent(handler) subscription that returns an
   unsubscribe function.

  5. src/index.html (edited)

  Why: No CSP, no UI to show update progress.

  Added:
  - Content-Security-Policy meta tag — default-src 'self'; remote scripts blocked, eval/new Function blocked, remote XHR blocked, <object> blocked,
  base/form action locked to self. 'unsafe-inline' is allowed for scripts + styles because the renderer uses inline onclick attributes pervasively
  (architectural; documented in CLAUDE.md). Google Fonts is explicitly whitelisted.
  - Update banner — fixed top-right glass card with title, message, progress bar, and Download / Restart-&-install buttons. Wired through
  window.api.updater.onEvent. Hidden until the main process reports available.

  6. .github/workflows/build.yml (rewritten)

  Why: It was running electron-packager (legacy) and uploading an unpackaged folder. Now it actually builds the installer your users will receive.

  Builds an unsigned NSIS + portable on every push/PR to dev/main and uploads dist/*.exe + dist/latest.yml as a workflow artifact for smoke-testing.

  7. .github/workflows/release.yml (new file)

  Why: This is the trigger for end-user updates — pushing a vX.Y.Z tag turns into a published GitHub Release.

  - Triggers on push of tags matching v*.*.* (also has workflow_dispatch for manual runs)
  - Verifies tag matches package.json version (fails fast on mismatched tags)
  - Runs npm run release which calls electron-builder --publish always
  - Uses the built-in GITHUB_TOKEN — no extra secrets needed
  - Code-signing env vars (CSC_LINK, CSC_KEY_PASSWORD) are commented out, ready to enable as soon as you have a cert + add the secrets

  8. build/.gitkeep (new file)

  Why: electron-builder looks in build/ for installer resources (icon, license, NSIS hooks). Empty placeholder + comment documenting what can go
  there.

  ---
  How the release process now works

  # 1. Edit code, commit normally
  # 2. Bump version (this also creates the git tag)
  npm version patch       # 1.0.0 → 1.0.1   (or `minor` / `major`)
  git push origin main --follow-tags

  That git push of the v1.0.1 tag triggers .github/workflows/release.yml, which:
  1. Runs npm ci
  2. Verifies the tag matches package.json
  3. Runs npm run release → builds dist/Zentra Finance-Setup-1.0.1.exe, the portable .exe, and latest.yml
  4. Publishes them as a GitHub Release named v1.0.1

  ---
  How automatic updates reach users

  1. App starts → 5 s later, autoUpdater.checkForUpdates() hits https://github.com/javadqasemi/Zentra-Finance/releases/latest/download/latest.yml
  2. If the version there is newer than app.getVersion(), the renderer's banner appears: "Version 1.0.1 is ready to download"
  3. User clicks Download → autoUpdater.downloadUpdate() pulls the .exe + .blockmap (the blockmap enables differentialPackage, so a 1.0.1 → 1.0.2
  update typically downloads only a few MB)
  4. When done → banner switches to "Restart & install"
  5. User clicks → quitAndInstall(false, true) runs the silent NSIS upgrade and relaunches the new version
  6. On the next launch in step 1, periodic checks repeat every 4 hours

  Errors (offline, GitHub down) are silent in the UI — they're logged to %APPDATA%\ZentraFinance\logs\main.log and retried up to 3× before giving up
   until the next periodic check.
